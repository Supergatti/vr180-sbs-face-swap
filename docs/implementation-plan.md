# VR180 SBS 视频换脸工具实施计划

日期：2026-10-10

本计划以最终可用的 VR180 SBS 视频换脸工具为目标，从需求重新确定架构。既有脚本和模型仅作为可复用实现，不限制新工具的结构。

## 1. 最终交付

用户选择来源脸、目标 VR180 SBS 视频、目标人物和输出位置，启动任务后得到：

- 能正常播放的 SBS 换脸视频，保持双目布局、帧时序、音频和适用的 VR 投影元数据。
- 左右眼分别定位、对齐与换脸，同一人物使用同一来源身份。
- 可切换的人脸增强、进度预览 PNG、异常帧记录和任务报告。
- 尽量减少漏检；可查看目标轨迹并修正漏检或错误关联，修正结果可用于重新渲染。

使用已有预训练人脸检测、换脸和增强权重，无需训练新 YOLO。粗框和裁片是内部数据及可选调试产物；第一阶段的交付物就是完成换脸的短视频。

首版几何输入为每眼 180° ERP 的横向 SBS。输入参数明确记录每眼的角度范围、方向和双目布局，后续通过投影适配器扩展其他 VR 格式。

## 2. 工具操作

1. 选择视频与来源脸，确认视频投影和左右眼布局。
2. 选择替换全部人脸或指定人物，设置速度/质量选项。
3. 启动任务，工具依次完成分析与渲染；监控图显示当前帧、目标编号和处理状态。
4. 播放结果，查看有问题的片段；需要时修正目标范围或身份选择，并重新渲染相应部分。

指定人物使用稳定轨迹和身份关联，不按每一帧的人脸排序重新选“第一张脸”。首次发现目标或关联存在歧义时，提供缩略图用于选择和复查。

## 3. 推荐架构：离线分析，然后渲染

### 分析过程

```text
解码 SBS
  -> 分离左右眼
  -> 生成覆盖有效视场的重叠透视视图
  -> 已有人脸检测器输出框、置信度、五点关键点
  -> 将检测和关键点转换为球面方向并去重
  -> 建立每眼轨迹、左右眼对应关系及人物关联
  -> 保存逐帧目标元数据、监控图与异常记录
```

分析结果保留每一帧的目标、关键点来源、实际相机参数和可信度。首次使用先完整扫描每帧；随后再加时序调度。

### 渲染过程

```text
解码原始全分辨率 SBS
  -> 读取当前帧的已选目标与关键点
  -> 从原图生成目标附近的高清透视区域
  -> 投影已知关键点，按需做局部关键点细化
  -> 对齐到模型模板、换脸、可选增强
  -> 将结果和遮罩逆投影回原始眼画面
  -> 重组 SBS、编码输出、保留音频与 VR 信息
```

两遍解码增加了读取成本，但能把按时间顺序的分析与可并行的渲染解开；修改人物选择或画质后可以复用分析结果。整体耗时按分析加渲染计算，不把任一阶段的 FPS 当作完成视频的速度。

## 4. 检测与几何设计

- 保留检测器已有的五点关键点，不能只保存粗框。已有 YOLOFace 同时输出框和关键点，渲染可复用这些当前帧信息。
- 起步使用每眼四个斜向视角加中心视角。最终视角数、FOV 和尺寸由有效角域覆盖、脸的投影尺寸和漏检样例决定，4+1 是可替换布局。
- 使用真实透视重投影；整张 180° 画面无法在一张普通有限视场透视图里同时保持合适的人脸形状。
- 每眼五片代表每 SBS 帧十个扫描视图。左右眼都保留新目标发现通路，以覆盖只在一眼可见的脸。
- 重叠区域中的检测先去重，再进行局部处理。跨片重复检测与双目对应关系分别处理；左右眼都需要独立换脸。
- 每个目标保存球面方向、角范围、五点关键点方向以及实际投影矩阵。回填使用对应的实际参数，不用粗略角度重新猜位置。
- 高清目标区域从原始图像采样，视角和尺寸按目标调整；检测图缩小不意味着换脸输入也从缩小图放大。
- 将检测视图中的关键点通过球面射线映射到目标区域，通常无需对高清区域重新跑一次 YOLO。关键点不可靠时使用局部关键点模型细化或局部重检测。
- 后续可将球面重投影和模型对齐的逆映射组合，直接从 ERP 采样标准化脸部输入；第一版先使用清晰可验证的局部透视实现。
- 检测阈值偏向保留候选。肤色不作为取消扫描或丢弃目标的硬门槛，候选由几何、关键点和时序一致性进一步确认。

## 5. 换脸、增强与回填

- 来源脸特征初始化一次，模型会话常驻；运行过程中以图像数组传递目标区域。
- 首版从模型原生尺寸换脸，例如 128 模型使用 128 pixel boost；更大的 pixel boost 作为后续画质选项，明确增加的推理次数。
- 换脸和增强使用各自模型的模板、输入尺寸和归一化。增强不直接假定兼容任意换脸模型的对齐图。
- 速度模式可关闭增强，质量模式对每个有效目标逐帧增强；同一段输出使用一致参数，避免周期性开关增强带来闪烁。
- 保留人脸融合遮罩，并将图像和遮罩一起逆投影，只修改原图中有效的人脸区域。
- 原始背景作为最终画面的底图，避免整块透视背景被重复投影后产生变形、模糊或接缝。
- 左右眼独立精细对齐、独立处理遮挡；共享来源身份和质量设置，不用一眼结果直接覆盖另一眼。
- 自动定位不可靠时记录异常；复查支持补充目标或排除误检，修正结果进入任务元数据。

## 6. 性能策略

成本模型按视图数与唯一人脸数分别计算：

```text
总耗时 = 分析解码 + 扫描投影 + 检测/跟踪
         + 渲染解码
         + sum(每帧、每眼唯一目标的采样/对齐/換脸/增强/回填)
         + PNG 监控写盘 + 视频编码与音频处理
```

- 固定扫描映射预计算，初版采用 CPU OpenCV 重映射，后续按端到端耗时决定是否升级 GPU。
- batch 检测是优先优化项，需模型和逐样本输出解码都支持。可用源权重重新导出涉及模型部署，不需要训练；源权重不可用时单样本路径仍能完成工具。
- 一张脸在多个扫描片中出现，也只进入一次每眼渲染；第二次 YOLO、重复身份特征和无用属性分类按实际需要安排。
- 帧、目标区域与模型结果通过内存传递，模型之间无需 PNG 或中间透视视频。
- 初版用一个 GPU 工作队列；解码、CPU 预处理和写出使用有界缓冲，后续再决定是否增加并发。
- 对回填限定目标像素区域，避免每张脸都复制、重映射整幅高分辨率画面。
- 监控 PNG 默认约每视频秒一张，首帧、异常和用户指定帧额外保存；支持每帧监控。裁片全量导出是可选调试设置。
- 缓存分析元数据和少量目标缩略图，不缓存全部高清透视片。输入或投影/检测设置改变时让分析缓存失效。

实际调用数由唯一目标数、双目情况和重试决定，不把“平均六次 YOLO”设为准确性限制。

## 7. 时序加速与漏检处理

离线分析天然有时间顺序，可以前后回查，而渲染读取每帧确定的元数据。

- 首版逐帧分析作为基准，先验证目标身份、几何和输出连续性。
- 轨迹记录球面方向、角尺寸、关键点与可信度。场景切换、快速相机运动、目标丢失和身份歧义触发重新发现。
- 稳定轨迹使用局部检测或关键点更新，全局扫描负责发现新目标。
- 快速模式可减少完整扫描频率。新目标在后续帧发现时回查之前的帧，补足入场位置；完全夹在复扫间隔内的短暂目标仍需要逐帧发现通路。
- 不能只对“整帧完全没检测到脸”补帧；多人场景中某一轨迹丢失也要独立处理。
- 轨迹预测安排当前帧搜索区域，当前帧换脸仍使用当前帧图像和有效关键点。
- 复查界面列出失配、关键点失效和目标突然消失的片段，便于发现漏检并定点修正。

高召回与快速设置分别保存，使用同一段样例报告速度和遗漏差异。

## 8. 实施阶段

| 阶段 | 工作 | 必须交付的结果 |
| --- | --- | --- |
| 1. 端到端最小工具 | 来源脸、SBS 解码、基本全视场检测及去重、局部换脸、遮罩回填、音视频输出、PNG 监控 | 一段约 10-30 秒可播放的 SBS 换脸样片，第一阶段就能看到最终效果 |
| 2. 人物与画质 | 指定人物、双目关联、关键点细化、遮挡与增强、轨迹预览和修正 | 目标稳定，左右眼身份一致，近脸和边缘样例可处理 |
| 3. 性能 | 分段计时、batch 可行性、关键点复用、有界流水线和局部回填 | 实际最慢环节明确，优化前后输出质量和遗漏可对照 |
| 4. 时序 | 轨迹驱动的局部更新、复扫、切场重置、离线回查 | 快速模式有明确的速度收益和漏检记录 |
| 5. 长视频可用性 | 任务保存、分段输出、断点恢复、音频/VR 元数据、错误提示和简洁界面 | 长视频可以完成或恢复，用户能复查并重新处理问题片段 |

无需等所有优化完成才提供可用结果。每一阶段都在已经能生成视频的工具上继续推进。

## 9. 验收与记录

- 分别查看左右眼的漏检、错误关联、关键点漂移、遮挡处理、融合边界及背景变化。
- 样例包括近脸、小脸、上下左右边缘、多人、进出画面、快速转头和切场；保留人工确认的目标记录。
- 视频输出检查帧时序、音频同步、左右眼布局、原始分辨率和播放器对 VR 信息的识别。
- 总耗时、分析/渲染分段耗时、首帧加载和稳态 P50/P95 分开；模型调用数、脸数和监控写盘字节同时记录。
- 现有约 3 秒/帧若对应粗检/导出，仅与相同工作量比较。完整视频处理建立单独基线，性能目标在第一段样片得到分段耗时后确定。
- 优化时保留工作配置和样片；每轮改变一个主要变量，漏检和双目画质不回退后再采用。
